**What "pytest exits 0 with the documented strict xfails" means, exactly.** In `pytest` (full) or `pytest -m "not slow"` every selected test passes or is one of these nine strict xfail cases: no failure, no error, and no unexpected pass. Because the marks are strict, an unexpected pass is reported as a failure and pytest exits 1, so exit 0 also asserts that the nine behaviours are still present. Because each mark sets `raises=AssertionError`, a body that fails for another reason (an exception from a refactor) is a failure, not an xfail. It does **not** mean: the plan's test items are met (section 4, departures 1, 2, 4), the estimator is right, or that there are no warnings (1 ComplexWarning from MS5 code). No global `xfail_strict` or `filterwarnings = error` is set in `pyproject.toml`; each mark carries `strict=True` itself.
