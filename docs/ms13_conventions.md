# MS13 figure conventions (frozen at 13b)

Source: the reviewer's acceptance of M13-1 to M13-13 as proposed in `docs/ms13_plan.md` section 6 (13b prompt; DL-425). This file writes the accepted choices in words. The plan (`docs/plan.md`) is not edited. **Everything here that the plan does not state is UNVERIFIED**: colours, markers, layouts, formats and file names are design choices, not scientific parameters, and none of them is a result. The one item still open is marked PENDING (section 11).

## 1. File formats (M13-1)
- Each figure is written as a vector PDF (for the paper) and a PNG preview (for review), from the same script and the same data; `<ID>_provenance.json` and `<ID>_params.csv` sit beside them. The plan names the provenance and params files and no image format (UNVERIFIED).
- A raster of 300 neurons with many spikes is drawn as a rasterised layer inside the PDF; the axes, text and markers stay vector.
- The format list is written in the provenance file (`outputs`). The plan gives no resolution, font or size; none is set here (UNVERIFIED, M13-14 (vii) stays open).

## 2. Colour and marker rules (M13-2)
- One fixed table in `plotting/style.py`, keyed by surge class (S+, S-rel, S-abs, S-sus, NS, D-tr, D-sus, D-none), by path (P1 to P5, NC1 to NC3) and by source (mean field, network, noise). The same class or path has the same colour and the same marker in every figure.
- No meaning rests on colour alone: each class and path also has its own marker shape (and line style for lines). No two classes share a colour.
- The palette itself is the reviewer's; this file proposes no hex value (UNVERIFIED as a design choice).
- Colour-blind criterion: **PENDING the reviewer's ruling** (section 11). No number is set and no colour-blind test exists.

## 3. Failures and failure regimes (M13-3; plan sections 2.6, 7.2)
- Every map, table and sweep draws failure cells and non-surge regimes with the same area, outline weight and legend weight as surge cells ("failure regimes get equal weight"). A9 failure labels (a) to (h) get their own panel in F6.
- Each figure carries a **FAIL-row strip**: the list of A11 rows with status FAIL that touch the figure's inputs. The scripts read the stored A11 table (`results/A11/a11_robustness.csv`); they do not recompute it. "Failed checks are reported, not dropped."
- Whether the strip is drawn on the figure or only in the caption is decided figure by figure in each build prompt (placement, section 9).
- Results touched by an RB6 failure are shown labelled FAIL (FS4 ruling, section 10).

## 4. Network disagreement with the mean field (M13-4; F1, F4, F5, G4)
- Network symbols are overlaid on mean-field results (the plan's convention). Where the network class agrees with the mean-field class the marker is one shape; where it does not, a different shape, labelled by the network class. The legend gives the counts (agree / disagree).
- Disagreeing symbols are never dropped from a map.
- F1 draws the network spectrogram and raster beside the mean-field trace for all six S8 headline records, not only matching ones. How many seeds are drawn in a panel is stated in the caption (UNVERIFIED: the plan gives no seed count).

## 5. Caption template (M13-5; plan 2.2 and the section 8 checklist)
Generated by `make_<ID>` from the same config values the provenance file records, so a caption cannot disagree with `<ID>_params.csv`. Parts, in order (layout UNVERIFIED):
1. one-sentence take-home message;
2. parameter regime: model, reference point, path, profile, T_ramp, N where used, sigma with its label "checked, not confirmed" where used;
3. spectrogram settings (band, window rule and W, step, taper), read from the frozen criteria file, never retyped;
4. what symbols and markers mean;
5. claim limits that apply, by ID (which IDs print in the caption and which stay in the strip is decided per figure);
6. provenance pointer (hash12 of `<ID>_provenance.json` and the tag if one exists).
Caption length limit: the journal's, not the plan's (UNVERIFIED).

## 6. Nordlie parameter tables, two stages (M13-6)
- Stage 1: rows from `make_param_table` of every input record, deduplicated into constant and varied values.
- Stage 2: the Nordlie sectioning (model, populations, connectivity, neuron model, input, measurement) by a fixed mapping from keys to sections. The mapping is ours (UNVERIFIED) and lives in `plotting/style.py` or a small helper; until it exists the `section` column is empty and says so.
- Written as `<ID>_params.csv` with columns `figure, panel, section, name, key, value, units, status, source_run_id, source_config_hash12, varied`. Every row names the input record and config hash12 it came from.

## 7. Build order (M13-7)
`style.py`, the provenance writer, the Nordlie writer and `check_clean_tree.py` first (13b). Then cheapest inputs first: F3, F2, FS1, FS2, FS5, FS4, FS3, F6, F4, F1, F5 last (heaviest inputs, plan 13a section 10). One sub-step per figure group, stop after each.

## 8. Tags (M13-8; DL-422)
A tag `fig-<ID>-v<k>` is proposed (with its message text) after a figure passes its tests and a clean-tree build, and is **created only when the user says so**. A tag is never moved; a rebuild from changed inputs is `v<k+1>`. Nothing is pushed unless asked.

## 9. Noise-free against noisy, solver-dependent onset (M13-9; G6-D1 to G6-D3)
F4 and FS4 draw the noise-free delay (mode D, DOP853) and the noisy or floored delay (mode N) as separate series; the solver difference (58.698 s DOP853, 58.879 s Radau) is shown as a band or a pair of markers, and the onset reading is named in the legend. G6-D2 is stated in the caption. No pooled series. The RB6 FAIL is shown, and results that depend on it are not hidden.

## 10. F5c, input reading, rulings of 13b
- **F5c (M13-10):** metrics (class, f_pk, onset, duration) against N = 1e3, 3e3, 1e4, 3e4 with all 10 seeds as points, the mean-field value as a reference line, and the no-ramp control (S9_ctrl) beside it, because G4-C3 says the network classes cannot separate ramp-driven from non-ramp records.
- **Code placement (M13-11):** `plotting/style.py`, `plotting/figures.py` (all `make_*`), `scripts/fig_<ID>.py`, and `docs/figure_map.md` generated from the registry of `scripts/ms13_inputs.py` so the two cannot drift. Splitting `figures.py` is an engineering change for the reviewer.
- **Input-reading rule (M13-12):** tables first (for F5, the A9 tables), series only for example panels and the hash check of inputs. The provenance file hashes every input it reads; a table-derived figure records the table's hash and row count.
- **Provenance machinery (M13-13):** reuse `provenance.git_info`, `environment_info`, `sha256_file`, `atomic_write_*` and the frozen-criteria loader.
- **M13-14 ruling:** any modified or untracked file makes the tree dirty, and `scripts/check_clean_tree.py` refuses; `results/` and `figures/` are git-ignored. A build without `--tag` may run on a dirty tree and is marked `draft`; a tagged build refuses a dirty tree.
- **FS4 reading (UNVERIFIED reading of Table 8.1 "Any RB6 failure -> affected results unused"):** results touched by an RB6 failure are not used as evidence in any claim, and are still shown labelled FAIL.
- **FS5 inputs:** A8 plus A6 and the A11 RB9 rows (an assumption beyond the plan; flagged in the FS5 caption notes).
- **Claim-limit placement:** the table in `docs/ms13_plan.md` section 5 stays a list; placement is decided figure by figure in each build prompt.
- **FS6:** not produced (S14, S15 not run, MS12-C1). The provenance writer refuses it.
